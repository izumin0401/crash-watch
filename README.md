# crash-watch

市場の暴落検知bot。毎日1回、Gmailで結果を通知する。3つのチェックで構成される。

1. **BTC監視**(`check_btc.py`): BTC-USDの現在価格・前日終値比の騰落率を取得し、
   下落率が -10% 以下なら「暴落」と判定する。固定の1銘柄を毎日追跡するウォッチリスト方式。
2. **日経平均監視**(`check_nikkei225.py`): 日経平均の当日騰落率が -3% 以下なら
   「市場全体の暴落」と判定する。個別企業のニュースではなく市場全体の異常を見る。
3. **日本株個別スクリーナー**(`screen_jp_stocks.py`): 特定の銘柄を指定するのではなく、
   「本日の値下がり率ランキング」「日本株 急落」のような横断検索で、
   その日たまたま急落した個別銘柄があれば拾い上げる方式。ウォッチリストを持たないので、
   事前に気づいていない銘柄の急落も拾える。ただししきい値は-25%以下とかなり厳しめ
   (東証では個別企業の決算ニュースだけで-10~20%程度動く銘柄が毎日のように出るため、
   その水準を「暴落」として毎日通知すると単なるノイズになる)。

## 仕組み

- クラウドの実行環境はBashからの外部API直接呼び出し(egress)が制限されており、
  個人アカウントでは許可ドメインを追加する設定もないため、価格・銘柄情報の取得は
  `WebSearch` ツール(検索エンジン経由)で行う
- 各スクリプトは取得済みの数値を受け取り、暴落判定するだけ
- 暴落判定時はスクリプトが非ゼロ終了する(exit code 1)
- 判定結果はGmailへ毎日メール通知する(暴落の有無にかかわらず送信)。ログファイルへの
  保存は行わない(通知が唯一の記録)
- リポジトリへのcommit/pushは行わない

## 実行方法

```bash
python3 check_btc.py --price 62977.49 --change-pct -0.5

python3 check_nikkei225.py --value 38500.12 --change-pct -0.8

python3 screen_jp_stocks.py --hits '[
  {"name": "○○ホールディングス", "code": "1234", "price": 980, "change_pct": -28.4, "reason": "粉飾決算発覚"}
]'
# 何も見つからなかった日は空配列
python3 screen_jp_stocks.py --hits '[]'
```

依存ライブラリなし(標準ライブラリのみ)。Python 3.7+ で動作。

## 自動実行

Claude Codeの Scheduled Cloud Agent (routine) から毎日実行され、
WebSearchで価格・銘柄情報を取得 → 各スクリプト実行 → Gmailで結果を報告する。

## しきい値

- BTC: 前日終値比 -10% 以下
- 日経平均: 前日終値比 -3% 以下(市場全体の異常)
- 日本株個別銘柄: 当日の下落率 -25% 以下(個別企業の決算ニュース程度のノイズを除外するため厳しめ)
- 各スクリプト内の `THRESHOLD_PCT` を変更すれば調整可能
- 為替は値動きの性質上(通常±1%程度)このしきい値では対象外

## 今後追加しうる資産クラス

- 米国株・その他暗号資産などのスクリーナー追加は要望に応じて拡張

## 既知の制約

- WebSearchのスニペットから数値を読み取る方式のため、直接APIを叩くより精度・安定性は落ちる
- 日本株スクリーナーはニュース・ランキング記事に出てくる銘柄しか拾えない
  (記事化されない小型株の急落は見逃す可能性がある)
- 過去の価格・判定履歴は残らない(毎日のGmail通知がその日の記録)
